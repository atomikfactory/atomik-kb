# Desktop smoke scripts (Windows)

The real-app pass of every milestone: start `pnpm tauri dev`, wait for the window,
drive the UI through Windows UI Automation (WebView2 exposes the DOM as UIA
elements: `Edit`, `Button`, `TreeItem`, ...) and `SendKeys`, capture the window with
`PrintWindow` (the only capture that works from a tool shell), and read the core's
logs. Dot-source `scripts/dev-env.ps1` first.

| Script | What it does |
|---|---|
| `launch.ps1` | Starts the dev app with `RUST_LOG` at debug for the shell, core and storage, waits for the window, dumps the UIA tree, captures `out/launch.png`, leaves the app running. Logs: `out/app.err.log`. |
| `drive.ps1 -Step onboard\|page\|type\|search` | Example steps on the running app: onboarding, a new page, typing with the slash menu and the page picker, search. Adapt the steps to the milestone. |
| `drive-m4.ps1 -Step kit\|lock\|unlock\|export\|restore\|verify` | Milestone 4 steps: create and check the recovery kit, turn the app lock on and lock, unlock after a restart, export a backup through the native save dialog, restore it with the kit on a fresh data directory, verify the restored page and search. Writes the kit words to `out/kit.txt`. |
| `drive-m5.ps1 -Step sample\|image\|check\|data\|purge` | Milestone 5 steps: write a sample PNG, insert it as an image block through the slash menu and the native Open dialog, check it renders, Settings -> Data counts and "Clean up now", trash the page before a collection. Reuses the helpers of `drive-m4.ps1`. |
| `server.ps1 -Action start\|stop\|reset\|status` | Milestone 6: runs `target/debug/kb-server.exe` on `127.0.0.1:8787` with the data directory `out/server` and the invite token `dev` (`reset` deletes the data: a new server epoch). Logs: `out/server.log`. |
| `launch-b.ps1 [-Fresh] [-Name b]` | Milestone 6: a second desktop instance on `out/<name>-data` (`KB_DATA_DIR`, debug builds) loading the UI from the running Vite server; prints its process id for `-AppPid`. Logs: `out/<name>.err.log`. |
| `drive-m6.ps1 -Step connect\|token\|status\|type\|check\|disconnect [-AppPid N] [-Text ...]` | Milestone 6 steps on either instance: Settings -> Sync connect (with the invite-token step when the server does not know the account), status line and sidebar indicator, type a line into "Smoke page", wait for a line to arrive from the other device, disconnect. Reuses the helpers of `drive-m4.ps1`; B is restored with `drive-m4.ps1 -Step restore` first. |
| `drive-m7.ps1 -Step join-start\|sponsor-start\|join-confirm\|sponsor-confirm\|join-wait\|devices\|rename\|revoke\|removed\|recover -AppPid N [-Name ...]` | Milestone 7 steps: pair a fresh instance by the typed code (the joiner's onboarding and the sponsor's Settings -> Devices dialog, the six digits compared through `out/pairing-sas.txt`), list devices, rename this device (every device is "Windows device" by default), remove one by name (saves the new kit to `out/kit.txt`), the removed screen, recovery with the kit from the server on a fresh instance. Reuses the helpers of `drive-m6.ps1`. |
| `drive-m8.ps1 -Step sample|insert|check|state|transfers|policy|download|saveas|remove|clean|blobs|deletions [-AppPid N] [-Kind image|file] [-Path P] [-Value V] [-Data D] [-MB N]` | Milestone 8 steps: a sample image and an N MiB file, inserting them in "Smoke page" on one instance, waiting for the block to complete on the other (the transfer card states seen on the way), the transfer line of Settings -> Sync, the download policy, the card's Download button, Save as... (size check), removing the block, retention and "Clean up now", blob counts per data directory, and the chunk deletions the local server logged. Reuses the helpers of `drive-m6.ps1`. |
